# Complexity recommendations for main_v3

This note is based on the current `formalization/main_v2.tex` (697 lines) and the 2026-09-28 status-entry outline. It does not modify either manuscript. `complexity-proposal.tex` is a proposed replacement section for the root editor to adapt.

## Important corrections and choices

1. **Do not conflate finality with block interval.** With a ready batch and honest initialized leader, every correct regional replica commits by `delta_R + 2 Delta_R` from the first proposal send. Its child may be proposed after `2 delta_R`. A transferable `>W_i/3` postcommit receipt at a regional collector is conservatively available after `2 Delta_R + 2 delta_R`; a consumer adds its complete-object path delay. Direct endorsements to the consumer can improve this by removing the collection hop. The old v2 bound `delta_R + 2 Delta_R + delta_P` is fine only for that direct route or if receipt aggregation is already included in `delta_P`.
2. **In-region replacement has a clear clock.** From the first correct quit, all quit by `Delta_R`, all enter by `2 Delta_R`, an honest new leader announces by `4 Delta_R`, and anchor re-certification takes up to `2 delta_R`. Thus `4 Delta_R + 2 delta_R` to first fresh proposal is conservative. Add fresh-batch receipt latency. Detection, failed successors and missing state lie outside this clock. Do not describe this as a delay from the original failure.
3. **Normal handoff clock.** `H_ij = F_i + D_i + X_ij + A_j` is the terminal-old-proposal to first-new-proposal interval; first new receipt is `H_ij + F_j`. Here `D_i` covers nonideal terminal drain, `X_ij` covers complete receipt/body delivery to the successor group including internal distribution, and `A_j` covers initial current-view re-certification. If measuring from an already available old final receipt, omit `F_i+D_i`. This directly honors the user's accepted `2 Delta_G + cross-region delay` intuition without hiding the proposal hop, receipt and bootstrap constants.
4. **Avoid double-counting finality when amortizing throughput.** For homogeneous terms of K application batches, the correct proposal-spacing average is `((K-1)I+H)/K`. The `F_j` of the first new batch is not part of `H`. When calculating receipt-to-receipt intervals instead, endpoint offsets telescope over repeated complete terms.
5. **Four required cases must remain visibly parallel.** Ideal regional sequencing, regional leader replacement, normal fixed-quota cross-region rotation, accident cross-region rotation. Passive status update is a control-plane cost only; it is never a fifth rotation or a quota reset.
6. **Explicit unaggregated certificates cost cubic bits under full forwarding.** Each `O(n_i kappa)` QC travels with up to `O(n_i^2)` proposal transmissions, so byte bound is `O(n_i^2 ell+n_i^3 kappa)`. Message count is still `O(n_i^2)`. The same certificate-list issue applies to NEWVIEW. A compact QC changes the assumptions and may need signer metadata/setup costs.
7. **Handoff transport costs need an actual delivery strategy.** The proposed `O(n_j)` outer messages assume an already assembled receipt at a reachable holder, directly sent once to each successor member. Bytes are `O(n_j(a_ij+n_i kappa+s_L1))`, where `a_ij` includes all missing ancestry, not automatically only one new batch. Faulty fetch attempts must be added. Bootstrapping the successor still costs quadratic messages and cubic control bits for the inherited all-to-all implementation.
8. **Committee is an abstract ordered-entry service.** Size `c` and threshold do not imply an internal consensus complexity. Keep `M_C,B_C,T_C` as parameters unless an actual agreement/coordination algorithm is given. Explicit certificate size is `O(c kappa)`, full fixed-index status map is `O(m)`, so L1 entry payload is `O(m+c kappa)`; internal observation, agreement, signature distribution and L1 network/consensus are different costs.
9. **Forced-cut liveness is conditional.** From outage, a conservative sequential upper expression is `T_detect+T_cut+T_C+T_L1+X_ij+A_j+F_j`. These phases can overlap. Do not promise tens of minutes or one hour without assumptions on cutoff discovery, recoverable data, committee progress and L1 progress. The user's tolerance can be stated as a design priority, not a derived guarantee.
10. **L1 relation is proof-system neutral.** No constant verifier/gas claim follows from abstracting verification into `R_rollup`. Finality in the sequencing stream, DA availability, transfer to proposer, and L1 settlement are separate timing endpoints.

## Scope and integration notes

- The fragment uses `C_i,F_i,I_i,H_ij,A_j` as local complexity notation and `T_i^{view}` for local replacement latency; it leaves `V_i` for the regional participant set.
- Communication bounds use `\mathsf{Msgs}_i` and `\mathsf{Bits}_i` to distinguish bit complexity from physical blocks `B_k`.
- Quota `K` counts application batches. Additional control blocks do not consume K but do consume communication and possibly drain time. Their number cannot be claimed constant through arbitrary failures without a progress assumption.
- The proposal-to-proposal normal boundary starts before the old terminal batch finalizes; the receipt-to-first-new-receipt clock starts afterward. Put one definition next to the main table to avoid readers adding the same old finalization twice.
- For group readiness, the stated `A_j <= 2 Delta_R + 2 delta_R` is measured after all correct successor participants possess the validated anchor and have the assumed readiness skew. If measured from first arrival at a single successor, include dissemination/readiness time in `X_ij`.
- A per-batch mini-block rate `u/I_i` does not imply each mini-block is independently finalized at that spacing: all mini-blocks in a batch are covered by that batch's final receipt.

No external protocol claim was added; these bounds are derived from the displayed v2 message and timer rules.
