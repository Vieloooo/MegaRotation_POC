## Healthy execution

1. Drive a prearranged healthy control signed once by the configured governance key, with the existing static policy, correct request and control sequence, and `beta_target` equal to the branch expected to be current at activation. A separate EVM transaction sender may relay it. Check EIP-712 domain and exact calldata fields, successful real receipt, Authority log topic/body, transaction and containing block identity and position. Correlate transaction submission, manual inclusion, online driver finalization and finalized reader delivery separately. Duplicate raw transaction submission, duplicate Authority request, and replay of identical finalized input are different observations.
2. Compute `x = ts_L1(including_block) + M_a` from the mined header timestamp in public time units. Before replaying the control, require a contiguous complete finalized L1 reader prefix covering `x − M_a` and a finalized Espresso reader prefix with watermark at least `x`, plus any additional Plan and anchor materials. While either coverage is absent the control contributes zero effects. The actual first processing observation is a virtual tick and can differ from `x`. Determine `q* = min{q | theta_q >= x}` directly from finalized Espresso blocks. Only Espresso q below q* belongs to the Force pre-state, whether due to staggered reader delivery or tied timestamp.
3. Derive the old G prefix and actual accepted head from replay immediately before insertion of the Force record. The successful transition outputs exactly one old branch closure and a new selected assignment when the PoC Plan is available, while the entire accepted G prefix, IDs and state roots are preserved. The new anchor carries the actual accepted head's physical/connection identity and execution state. Its height or the head at request time alone is insufficient. The new beta is old beta+1, and the L1 floor is max(old floor, including block height). The old responsible region is the new boundary's source region, and the anchor is the reference block. For an already contributing NEXT, use active old r+1. For a NEXT that has yet to contribute a physical result, reuse active old r. For PENDING use its stored r and source region. Derive `region=(beta_new+r_new) mod 3`, `h_min=max(A.h+1,slot(x+T_init)+1)`, `h_max=h_min+9`. Recompute cid from frozen canonical descriptor inputs, including exact anchor identity and new Plan. Check window and source validation are independent of local clocks and reader arrivals.
4. Each worker that has an old branch cid must close it permanently, including assigned/preparing, ready, running or paused entries. Existing old terminal reasons and historical outputs survive redelivery. Any pending preparation completion or old proposal, vote or timer after termination must leave the instance terminal and produce no new signature. Use actual post-close entry/signer-path stimulus where possible and verify zero old-cid signing or outbound new signed subject by ordered grant, durable record/Ack and release. A valid certificate made from pre-close signatures remains valid; demonstrate that an old result whose complete public position is at or after x cannot increase G after the successful Force. Confirm it is a valid old result of higher physical height than the held G head or the case can pass by duplication alone.
5. Check new worker Ready against verified state bound to cid+anchor, and Enter after that worker's Ready on its independent schedule. Sufficient quorum weight and a viable leader must be ready for the declared earliest-start profile; record each actual virtual Ready and Enter separately. Earliest honest local opening in virtual coordinates is `ts*(h_min) − δ_G`. Check configured v2 readiness inequality `T_init >= Δ_ts + T_E + T_replay + T_state + δ_G` when claiming the bound; observed receipt/finalization/public visibility, replay and preparation timings are separately measured. Use the frozen profile's success deadline and the strict public expiry bound for the original next missing height `ts*(A.h+1)+W_exp`, including any padding heights.
6. Prove success on first new branch admission. Independently check Simplex Finalization against the exact new cid/namespace, epoch and view, subject/payload digest, and ≥4 distinct registered signers; verify complete available body chain, execution metadata and required L1 origins. Determine first public completeness q_avail from finalized ordered public bytes. Check first qualifying physical result's ancestry extends A, physical heights are within the new window, virtual entries begin at A.h+1 continuously (including required padding), publication key is strictly below new SessionEnd, and acceptance key is strictly less than each appended height's expiry. Distinguish native finality, publication, public completeness and acceptance. Compare independent replay and reader output at matching public positions. Record same process identities and normal exits for all 15 workers, timing in protocol units apart from wall time, and lack of unintended restart.

## Deterministic vectors

| Input and precondition | Expected result |
| --- | --- |
| Receipt successful, L1 inclusion visible but unfinalized, or finalized L1 absent from reader's prefix. Espresso covers the key. | No control application or closure; wait. After L1 coverage arrives, replay the same event at the original key. |
| Force in finalized reader L1. Espresso watermark is strictly below x, then reaches x. | No early activation; one transition on joint coverage with pre-state head determined by q below q*. |
| Old regional result published with key x−1, followed by old result with key x. Both valid and otherwise admissible. | First contributes to activation anchor; latter does not. The new branch starts from the exact retained first-result identity. |
| Force x equals previous NEXT SessionEnd and old publication; old NEXT has contributed. | Force first, BranchClosed and new assignment. Old SessionEnd becomes inapplicable; no duplicate handoff. Old tied publication cannot add to G. |
| Same L1 block multiple Force records, with later controls either still targeting old beta or targeting the branch a prior valid control creates. | Replay exact tuple (L1 block, transaction index, log index) order, independently of sequence sorting or delivery; evaluate validity on then-current state. Stale record is a no-op. |
| Force x and Expire h at x, with SessionEnd and multiple Espresso q at x. | Controls in L1 position order precede Expire. Expire still targets next missing h after Force if G unchanged, and can halt the new branch. Active SessionEnd is evaluated after Expire. Use independent paired cases/comparator fixture as needed to expose SessionEnd-before-Espresso and tied Espresso by ascending q without invalidated timers. |
| Force submitted while session s contributes; full-window regular or valid SessionEnd moves responsibility to s+1 on same beta before activation. New NEXT has contributed zero physical results. | The unchanged target branch still permits Force. Anchor is the actual post-handoff prefix head; use successor's same r and region as source, not original request-time session or r+1. |
| Correctly signed successful Authority record whose target is stale or whose target branch is current but Tail HALT by activation. | One public replay record at its ordered position with empty effects and no lifecycle. G/branch/policy/floor remain unchanged for the control transition; HALT remains HALT. |
| Wrong signer/domain, stale sequence with fresh request identity, or same request identity with changed valid signed content sent to Authority. | No successful control event or sequence change. Preserve a failure receipt or transaction submission failure and independent Authority state/log check as applicable. |
| Exact Authority request retry using valid signature and a new EVM transaction/nonce. | Successful receipt may return the original result, with no additional ForceRecorded, sequence change or downstream activation. Verify it is a distinct mined transaction. |
| Identical public L1/Espresso prefix or identical lifecycle event delivered again. | Same processed position and state, zero additional branch transitions or cid creation/Enter. An already-terminated old cid remains terminal. |

The real healthy profile establishes bounded integration evidence. Focused state inputs for exceptional rules establish those guard transitions independently of the 15-worker profile. Neither evidence substitutes for automatic detection, restart recovery, or performance outside the recorded profile.
