# H3 additive expectations v1

2026-11-16. Added after the initial source-derived28-case table and after reading the H3 interface proposal, following lead discussion. These additions independently recheck the same primary rules and exact accepted component APIs; no H3 implementation exists or was inspected. They are not retroactively part of the pre-proposal chronology. Every case is **NOT_RUN**.

**E9a — Capacity applies to the complete attempt and fanout.** Existing06 validates the entire immutable `publication_messages` list using the one-block envelope bound before Offer becomes QUEUED (`publisher/src/lib.rs:379`, `src/codec.rs:414`). Transport fragmentation cannot relax this public capacity or silently create multiple durable attempts. Inclusion across multiple q is nevertheless supported: frozen06 §4.1 explicitly permits proof at q1 and bodies at q2, and `confirm_recorded` accepts `publication_position.q <= complete_through_q`. A controlled service can custody one complete bounded attempt then propose its unchanged constituent messages at different q; H3 must freeze pending-list admission/ack semantics and track each occurrence. This is the real public proof-first/body-later case. Delaying transport fragments of one q tests only local prefix WAIT. H1 observing a proof before bodies still cannot create a complete Offer.

02's configured payload limit may be smaller than its 65,536-byte maximum. The fragmentation size must obey that exact configured value. Its default global queued-payload limit is 4 MiB: blindly enqueuing fifteen 1 MiB copies exceeds it, with positive framing overhead making even four full copies exceed 4 MiB. Freeze endpoint/channel credits and a bounded enqueue/drain schedule with H1; retain reliable custody if admission/backpressure delays frames, and never reinterpret dropped/missing fragments as public absence.

**E5a — Local safety fences are not a readiness barrier.** GFR event atomicity and H2's per-worker application cursor are distinct. An already committed record may await a particular worker's successor material; another worker can progress independently. Pending new assignment must never bypass that worker's permanent Program Close, TIME or ClockUnsafe guard. H2/H1 must freeze the exact immediate durable close fence and batch acknowledgement policy. No all15 Ready/Enter barrier is permitted, and no proposed H2 API is treated as already implemented.

**E12 — Recording does not require selection.** v1004 §3.5 says complete finalized publication produces Recorded and separately defers acceptance to GFR. A valid complete candidate may be public, and therefore recorded, while another cid remains selected. The recorded validator must authenticate the candidate descriptor/Plan/anchor source, finality, exact physical bodies and original positions directly; it must not require current Tail or infer recording from G append. Publisher's complete-result provenance requirements remain stricter than GFR's selected-anchor q_avail optional-evidence boundary. A closed or unselected candidate's complete historical publication can still be recorded without reopening retry.

**Proposed shared completeness helper:** an exported pure07 capability that checks proof+public-body completeness for a supplied independently validated descriptor/anchor is consistent with this separation if it excludes selection, session cutoff, Expire and G mutation. It must run VerificationBasis before bool verification; preserve original source locations; distinguish public absence from locally missing input; return deterministic completeness evidence usable for receipt validation, and not weaken Publisher's separate AnchorEvidence/Plan verification. H3/07 owns the helper, H1 owns the native checker, H2 supplies validated candidate/source materials. This is an unfrozen API proposal requiring exact signatures, ownership and affected07 regression verification. Merely querying current07 ReplayState.publications cannot establish an unselected candidate's completeness where evaluation is restricted to NEXT.

**Native-cutover review addition:** frozen07 §§3/9 already prohibit fixture→Native profile relabeling without revalidation. The final H3 contract §3.1 matches that source: exact H1/03 version/registry/PoP/CID/namespace compatibility first; expected Native binding, no fallback; checked genesis and genuine-input replay; shared real verifier/basis; then native mutations on the reviewed candidate. Reuse of raw bytes requires revalidation. Local Close/Pause/ClockUnsafe must not disable public historical verification. Any03 version/API change requires its explicit single-owner gate. This is an additional review conclusion under existing H3-01–03/17/32 coverage, not a claimed executed case.
