# I1 interface annex v1 — frozen by lead, 2026-11-15

Applies to task-contract-i1-v1, I1a. The exact interface is `poc/proto/i1.proto` and the hash helpers in `poc/crates/types/src/lib.rs`. Lead owns both. Clock operations are carried in controlled gRPC stream frames; Register binds identity before stream Hello. One globally outstanding grant, complete Ack, journal synchronization before Ack release.

## Encoding and bounds

Prost 0.14.4 encoding of the typed protobuf messages is the canonical logical encoding; no maps exist in protobuf. Unknown fields follow standard protobuf semantics (ignored before canonicalization). Unknown schema versions, absent/unknown oneof operations and invalid enum values are rejected. Every identifier described as a hash is exactly 32 bytes (optional cid may be empty where declared). Only node IDs 0/1 in I1a. gRPC frame maximum 1 MiB; payload maximum 64 KiB; per-link/channel queue maximum 64. Overflow drops newest visibly. Register, frames and envelopes validate run/node/incarnation/config bindings. Logical hashes omit transport incarnation by setting it to zero, permitting only explicitly authorized recovery replay.

`hash_parts(domain, parts)` = SHA256 of each domain/component prefixed by its u64 big-endian byte length. Protobuf scalars otherwise follow protobuf encoding. Grant/Ack self-hash fields are cleared before hashing. Tie hash uses domain `I1/tie/v1` and seed/event ID encoded as u64 big-endian separate components. SignedIntent hashes bind run/config/cid/node/slot/subject; they are fixture digests, not signatures. Envelope hash binds actual bytes. Typed state serialization uses stable struct ordering and BTreeMap ordering; no unordered collections/floats contribute to logical hashes.

## Runtime choices

Fixture starts at reference tick 1,000,000 us, nodes 0/1 have epsilon +1000/-1000 us. rate_profile_ref hashes `fixed-rate-one-v1`. Normal requests/response each cost 250 us; baseline lease length 100,000 us from sample time, refresh interval 20,000 us where a scenario enables automatic refresh. Request transit, service sampling, response delivery are separate trace events. ClockView projects as-of plus elapsed virtual time. For exact offset baseline uncertainty is abs(epsilon); it must fit <=1000. Stop is an absolute local deadline. Default stop 1,300,000 us. Work duration 5000 us (nonzero); link delay 20000 us, jitter zero unless configured. Clock/domain/config IDs derive deterministically from run configuration, never PIDs/ports.

Seed set: 7,42,99. Baseline and wall-pause variants use identical run_id/config/seed. Worker startup order, hub/worker/RPC/journal pauses (0 vs <=2 ms each) differ only in diagnostic options. watchdog=30 seconds of wall time; reports infrastructure failure, never protocol elapsed time. Builtin scenario CLI is `sim-hub --scenario NAME --seed N --output DIR [--wall-pause-ms N] [--reverse-start]`; CLI writes full resolved scenario and manifests. Scenario names and exact action schedules must be recorded in each output. Minimal suite: healthy, clock-faults, lease-expiry, timers, close-work, restart-before-ack, restart-after-expiry, network-faults. Additional negative unit cases cover every contract row.

Input RequestSample explicitly initiates a request. Create does not implicitly Enter or declare anchor ready. AnchorReady + valid delivered sample precede Enter. Repeated Enter/Close are idempotent. Recover resets transport calibration, not signing/terminal/timer state; a fresh delivered sample is needed before new work. No scenario may manually set a worker clock.

## Journal framing

Per-worker append-only journal. Each frame: u64 big-endian payload length, canonical UTF-8 JSON StepCommit bytes, 32-byte `hash_parts("I1/journal/v1", [payload])`. Max record 16 MiB. StepCommit includes monotonically increasing journal_seq, previous_record_hash, full resulting durable fixture state, logical_step_id, grant_hash and complete cached Ack. State hash excludes journal/cache metadata to avoid recursion. All complete frames verify checksum, chain, run/config/node identity and sequence. Complete corrupted frame fails closed. Only a final incomplete frame may be truncated to the last verified offset before retry. On initial journal creation, sync journal and parent directory; append + sync_all completes before any Ack is transmitted. Journal state contains accepted sample/request counters, absolute timers/generations, terminal/sign-once history and first receive records. Named test fault checkpoints: before_append, partial_tail, after_sync_before_ack, after_hub_commit. No step output may escape before completed sync. Recovery may return a cached logical Ack only when the hub explicitly retries its known grant hash under the new transport incarnation; copied obsolete frames are otherwise invalid.

## Lead freeze amendment 1

Use the hash framing above. Config is `I1/config/v1` over compact serde JSON of the resolved Scenario struct, including seed, actions and profiles. Wall pauses, process start order, ports and PIDs are diagnostic. Run uses `I1/run/v1` with config hash. Cid uses `I1/cid/v1` with a UTF-8 fixture label, currently `first` or `next`. Clock domain uses `I1/clock-domain/v1` with run ID, config hash and node ID as big-endian u32. Rate uses `I1/rate/v1` with `fixed-rate-one-v1`. Payload uses `I1/payload/v1` with raw bytes. Message uses `I1/message/v1` with run ID, source, destination and channel as big-endian u32, cid bytes (empty for absent), sent tick as big-endian u64, and payload hash. Intent uses `I1/intent/v1` with run ID, config hash, cid, node as big-endian u32, slot as big-endian u64, and subject. State uses `I1/state/v1` with compact state JSON. Journal uses `I1/journal/v1` with compact StepCommit JSON.

StepCommit JSON fields in order are `journal_seq, previous_record_hash, resulting_state, logical_step_id, grant_hash, ack`. State fields in order are `run_id, config_hash, node_id, fixtures, timers, first_received, sample_request_counter, outstanding_requests, accepted_sequence, prior_lease_end_tick_us, sample, last_tick_us, runtime_incarnation`. BTreeMap keys are lowercase hex cids/message IDs or JSON decimal representations of u64 keys in numeric order. The fixture fields are `descriptor, created_at_tick_us, anchor_ready_tick_us, entered_at_tick_us, view, terminal, paused, signed_intents, pending_work`. Terminal records store `reason, tick_us, lease_end_tick_us`. A pending work record has `work, due_tick_us`. Timer state stores `timer, active, observed`. First receive records store `envelope, first_tick_us, first_local_time_us`. A missing valid clock leaves local time null and the raw arrival recorded without protocol admission.

Prost handles duplicates before canonicalization. Singular scalars and bytes take the last value, repeated fields append, repeated embedded messages merge, a repeated same oneof message variant merges, and changing oneof variants replaces the old one. Scalar defaults are validated semantically. Canonical identity concerns decoded messages. Vendored protoc is 36.2, executable SHA-256 `f6ee22d65361338459208da8bff801c9ca689741cba9187b34990dd45198f864`.

A restarted worker receives explicit authorization to replay only the hub's known outstanding logical step/hash with a durable cached Ack. The new transport incarnation wraps the original grant with the same digest. A precommit interrupted step is recorded as aborted. Recover runs first in the new incarnation and clears calibration. Once a fresh sample arrives, the hub may reissue pending work in a new grant while retaining its original due tick. The hub defers other protocol inputs through recovery and calibration. A delivered envelope while calibrating records its original raw arrival with no local time or protocol admission.

The journal frame starts with u64 big-endian length and its u64 big-endian bitwise complement, followed by payload and checksum. Adjacent `journal.head` is an 88-byte committed floor. It contains ASCII `I1HEAD01`, big-endian offset and sequence (u64 each), 32-byte last record digest, then `I1/journal-head/v1` over the run ID, config hash, node u32 big-endian and preceding 56 head bytes. Initial empty offset/sequence/hash are zero. Create and sync both files and their directory. Append and sync the journal, write and sync `journal.head.pending`, rename it onto `journal.head`, then sync the directory before Ack. The `after_record_sync_before_head` crash occurs at the named intermediate boundary. Recovery verifies the entire committed floor and fails on corruption or missing committed bytes. An incomplete trailing frame above the floor can be truncated. Exactly one fully verified record above the floor can be synced and promoted to the floor and replayed with the same explicit authorization. Corrupt complete records fail closed.
