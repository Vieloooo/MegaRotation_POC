## 2. Size and transport decision

02's configured `Message.payload` bound is **at most**65,536 bytes;06's **message body** limit is65,536, but the06 block is `47 + source_id.len() + Σ(8 + message.bytes.len())` bytes, maximum1,048,576. Public GFR objects must each fit the existing message bound. A transport wrapper consumes additional bytes, so equal numeric message limits do not imply one packet can carry every public message. Bind the actual02 limit and require chunk+header to fit it.02's shared default queued payload budget4MiB also needs controlled credits/recipient batches: simultaneous1MiB fanout to15 readers cannot be assumed to fit. Retain reliable custody/backpressure; do not bypass02 or treat capacity loss as public absence.

Propose H3-owned, bounded transport-only fragmentation/reassembly of exact06 encoded bytes. Each frame including metadata fits02's payload limit; bind run/config/source/destination/incarnation/channel/codec, immutable object digest and length, ordinal/count and controlled origin. Bound retained objects/bytes and reject conflicting fragments before allocation. Do not send public fragment objects. Only exact fully reassembled authenticated06 objects enter the reader; an incomplete earlier block/message keeps the reader prefix pending. Reassembly tick never replaces public `(q,index)` or `q_avail`. H1 must confirm channel registration, endpoint bindings and controller effect admission; H3 freezes the frame layout and limits before implementation.

Public objects are still split only along existing Body/FinalProof object boundaries. A single oversized GFR object rejects before Offer; transport fragmentation cannot make an oversized public object valid. **06 validates the entire `publication_messages` list as one block**. Freeze a bounded M1 manifest whose largest complete result fits that limit; an oversized list is an explicit capacity/integration gate, never silently split into several durable attempts.03 allows at most1024 fixed-width19-byte transfer transactions per physical body and the session window allows at most10 physical bodies; actual encodings and the H1 proof bound still require measurement/handshake before coding.

A fully validated immutable attempt may place its existing proof/body messages at **different public q** through a bounded controlled service mempool retaining original AttemptId and message ordinals;06 contract§4.1 permits proofq1/bodyq2. It remains one complete Offer and one immutable attempt; partial H1 proof observation never releases a partial Offer or uses a dummy PhysicalBlock. This is distinct from fragment arrival delay. Publisher receipt preserves earliest target-proof publication position and actual complete-prefix basis; GFR earliest completeness remains a separately computed fact.
