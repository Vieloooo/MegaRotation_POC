# v3.6 独立审查结论

状态：**两个接受接口缺口已有修补，但完整活性仍未通过。** 本轮是新的三名独立审查者，未复用写作者或上一轮审查结论。

准确快照主源 SHA256：`ef6d858b8ead057dd77f1a43e4198d47ceceb016e5c7b826eb941878b59d96d5`。三份报告均核对全部 21 个快照文件及嵌套基线；源码未在审查期间改动。英文稿 67 页，编译与页面检查完成，Model 与中文第 2 节继续保留 v3.1 原文。

## 1. 两项修补取得的结果

对支持的完整结果格式，审查者认可：

- 错误的外层 base、beta、interval，或无关坏条目，不再否决完整且兼容的下一条 DATA。接受使用签名结果和真实祖先路径。
- 当前 terminal DATA 的提交、计数和公开先于下一 authority 查询。quota 为 1 时，不再因为后继尚未准备好而拖住首个正输出。
- 逐 DATA 提交有明确的记录内处理位置；后继等待不回滚已经公开的 G；重复输入不重复计数。
- Force prelude、旧 beta 匹配、MSIG 优先、同块新 beta 限制和旧版本截止规则保留。

[安全审查](fresh_safety.md)在这些明确接口及原区域模型下未发现 Critical Error 或实质 Justification Gap，也未找到模型内分叉／回滚反例。它不是对任意 native adapter 或传输编码的安全认证。

## 2. 剩余的公共依赖获取问题

[活性审查](fresh_liveness.md)指出一项 Justification Gap：之前收到过某个公共对象 X，不代表以后仍保留它的完整字节。

一条合法的时间线是：

1. X 在早期 Espresso 原始记录里，按 T_E 正常可见，但没有进入 G。
2. 节点后来保留了位置、checkpoint 和索引，把 X 的完整字节移到档案存储。
3. 新记录合法引用 X；节点需要重新获取它，才能形成完整 SOURCESTEP。
4. 冻结模型只保证旧历史可取回，没有为这次读取提供统一时限。

区域 Delta 从完整消息已形成并发送后起算，不能替发送前的旧依赖获取补上时限。因此当前公共响应界 L、时钟求和证明及地区服务结论仍有这个未证明的前提。审查没有据此证明全球进展定理必假；它指出当前证明尚不足。

下一版需要明确哪些字节必须跨 session、beta 和 worker 退出持久保留，checkpoint 可以释放什么，以及 finite preparation 怎样覆盖已有历史。修补应是协议存储与处理规则，不能增加新的档案读取速度假设。L1 authority 引用也须单独核对，不能笼统套用 Espresso 的 T_E。

## 3. 传输与处理合同还需形式化

[传输与假设审查](fresh_transport.md)未找到支持格式内的新错误包装攻击，但要求补齐两项精确覆盖关系：

- 新的对象解码／公共引用规则，如何覆盖原 v3.1 中已经交付的完整逻辑结果，不能只断言“旧格式也适用”。
- 完整 SOURCESTEP、状态采用与提交的哪些动作由已有 Delta 覆盖；原生恢复、序列化或外部读取不能仅因被叫作 handler 就自动获得上界。

这两项被列为 Justification Gap。没有给出的部署二进制编码或数据库实现，仍只能保留明确的实现义务；不能用成功编译 LaTeX 代替它们的证明。

## 4. 完整目标仍未完成

请求 inclusion 的原反例仍成立：被接受的 Byzantine 空 DATA 可以持续推进高度，而正确请求反复落在 Force 截断的后缀。更早的 Force 甚至可能使请求只得到一个 FINAL，不能形成受 T_pub 保护的完整结果。所以“收集迟到完整结果里的请求”也不能单独解决入口问题。

另需保留模型范围：当前地区服务命题讨论满足既有区域故障与通信条件的 eligible region；它不等于允许其他被选择的地区永久失去正确 quorum，同时仍宣称原模型成立。

v3.7 的设计工作正在分别处理完整公共依赖保留与原逻辑传输格式的对应关系。请求服务继续单独研究；尚未向正文加入新请求发布保证、改变冻结假设或把主目标标为完成。
